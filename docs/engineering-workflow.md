# Engineering workflow

## Prerequisites

- **Nix with flakes** — provides the dev shell (Node 22, pnpm 10, Rust stable, Tauri system deps, `git-cliff`). See `flake.nix`.
- **Radicle CLI** (`rad`) — for clone, patches, issues. See [radicle.xyz](https://radicle.xyz).
- **Docker** — only for reproducible release builds (`make build`).

Direnv is supported via `.envrc` (one-time `direnv allow`).

> **Note (non-NixOS + NVIDIA):** the nix devShell mixes nix WebKitGTK with system NVIDIA EGL, which can crash the dev binary at startup. On such systems, install `pnpm` and `rustup` via your distro and run commands bare.

## Local development

```bash
nix develop                 # or direnv allow once, then automatic
pnpm install                # first time
pnpm tauri dev              # Vite + Tauri with hot reload (port 1420)
```

Frontend-only build:

```bash
pnpm build                  # tsc + vite build
```

## Verification before submitting a patch

```bash
pnpm build                  # type-check + build the frontend
cargo check --manifest-path src-tauri/Cargo.toml
```

No test suite or linter is configured. If you add one, update this section and AGENTS.md.

## Branches and commits

- Work happens on `master`. There is no branch convention enforced.
- Commit messages follow **Conventional Commits**: `feat:`, `fix:`, `chore:`, `release:`. `git-cliff` consumes these for `CHANGELOG.md` — non-conforming commits won't appear in the changelog.
- Release commits are auto-generated by `make release` as `release: vX.Y.Z`.

## Patches (Radicle PRs)

The canonical repo lives on Radicle. Code review and contribution happen through Radicle **patches**, not GitHub PRs. See [ADR-0008](adr/0008-radicle-canonical-github-mirror.md).

```bash
git checkout -b feat/my-thing
# ... commits ...
rad patch
```

Patches are linked to issues by including the 7-char prefix of the issue ID anywhere in the patch title or description. See [ADR-0006](adr/0006-patch-issue-linking-via-hex7.md).

## Architectural changes — write an ADR

If your patch changes any of the following, write or supersede an ADR under `docs/adr/`:

- State management approach (App.tsx orchestration, contexts).
- Sync cadence or sync mechanism (polling intervals, switching to events).
- Config storage (home repo RID semantics, where `LocalConfig` lives).
- Terminal architecture (PTY backend / frontend bridge).
- Patch↔issue linking convention.
- Kanban column derivation (the `state:*` and `priority:*` conventions).
- Release pipeline (Makefile sync, GitHub mirror, Docker build).

Use [`adr/template.md`](adr/template.md). Number chronologically — append, never insert mid-sequence. See [`adr/README.md`](adr/README.md) for the renumber procedure if back-dating creates an out-of-order ADR.

## Releases

`make release` does the full ceremony locally:

1. Read current version from `package.json`.
2. Bump patch (or use `VERSION=x.y.z make release`).
3. `sed -i` the same version into `src-tauri/tauri.conf.json` and `src-tauri/Cargo.toml`. See [ADR-0009](adr/0009-version-sync-via-makefile.md).
4. Regenerate `CHANGELOG.md` via `git-cliff` (config in `cliff.toml`).
5. Commit + tag `vX.Y.Z`.
6. Push `master` and tags to **both** `origin` (GitHub) and `rad` (Radicle).

The tag push triggers `.github/workflows/release.yml`, which builds Linux (Ubuntu 22.04) and macOS (macOS 14, aarch64) artifacts and SCPs them to the project VPS — stable filenames at `dl.mikolajczyk.org/radboard/latest/`.

`make rerelease` force-retags the current version and force-pushes — use only to re-trigger a failed CI build.

## Machine-managed files — do not edit by hand

- `CHANGELOG.md` — regenerated by `git-cliff` on each release.
- `Cargo.lock`, `flake.lock`, `pnpm-lock.yaml` — managed by their respective tools.
- `target/`, `dist/`, `.docker-target/`, `result` — build outputs; gitignored.
